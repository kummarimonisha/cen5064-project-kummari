# ADR-003: Protect the AI feature with a shared access token and env-var secrets

Date: 2026-11-15  Status: accepted

## Context
The resume analyzer's AI bullet-refinement feature calls Google AI Studio
(Gemini), which spends real quota from the owner's account on every call. The
repository is public, so two risks must be controlled: (1) the API key must
never be exposed in the public code, and (2) anonymous visitors must not be
able to trigger paid AI calls and exhaust the owner's credits. Full user
accounts with passwords are out of scope for this course.

## Decision
- The Gemini API key is read only from the `GEMINI_API_KEY` environment
  variable (via a git-ignored `.env` locally, or host secrets in production).
  It is never written in code. A committed `.env.example` documents the
  variable names without values.
- The `/api/refine` endpoint is gated by a shared secret: callers must send the
  `AI_ACCESS_TOKEN` value in an `X-AI-Token` header. The token is checked before
  any Gemini call, so a missing or wrong token costs zero API credits. If no
  token is configured on the server, the AI endpoint is closed to everyone
  (fail safe, not fail open). The free local features (parse + ATS score) stay
  open to all.

## Consequences
- **Positive:** the public can see and run the app and the free analysis, while
  only the owner and people given the token can use the paid AI, protecting the
  key and the quota.
- **Positive:** the token check runs first, so abuse attempts spend no credits.
- **Negative:** a single shared token has no per-user tracking or revocation; if
  it leaks, it must be rotated for everyone. A future ADR could add per-call
  rate limiting or real accounts if the project needs them.
