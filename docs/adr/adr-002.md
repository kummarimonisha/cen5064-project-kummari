# ADR-002: Utilizing FastAPI Swagger UI for Initial Working Slice

Status: accepted

## Context
The midterm deliverable requires a working slice demonstrating a core use case traveling end-to-end (UI → logic → storage). Building the full React/Next.js frontend (Issue #4) concurrently with the core domain logic risks violating the single-responsibility principle of our sprints and introduces unnecessary scope creep for the midterm deadline.

## Decision
We will use FastAPI's auto-generated Swagger UI (`/docs`) as the Presentation tier for the midterm working slice. It allows users to upload a PDF/DOCX and input job keywords via a web browser, fully exercising the Service, Domain, and Data tiers without requiring a custom frontend yet.

## Consequences
- **Positive:** Guarantees a fully testable, run-ready end-to-end slice for the midterm.
- **Positive:** Keeps focus on the Domain tier business rules (ATS scoring) rather than UI styling.
- **Negative:** The presentation layer is technical and not candidate-friendly which will be resolved when the Next.js UI is built in the second half of the semester.
